# STEP 18 report

Built on the Step 17 code. Everything below says what was actually run in this build environment (Ubuntu, Go 1.22.2, Postgres 16, Node 22, 1 CPU, 4 GB). Nothing is claimed that was not run.

## What changed

### 1. Room join, joined state, notices
- **Diagnosis.** The server's join and leave notices (`rs` frames) already worked for people viewing a room, including community rooms (new test confirms). I could not reproduce a server-side failure. The real faults were:
  - official rooms never had a Joined state at all (the server only sent `j` for community rooms);
  - the page decided "Joined" by itself, the server never confirmed it;
  - the Join pill lives on the list tile, which is hidden the moment the room opens, so the change was never visible;
  - repeated taps on Join were not guarded.
- **Fix.** The `joined` frame carries a server-confirmed `j` (community: recorded member or host; official: being in the room). Official rooms report `j` in room lists while a connection, or the 30 s grace period, is present. The page shows "Joining...", then "✓ Joined" with a distinct style, shows a Joined/Visiting pill inside the room, ignores taps while waiting, and clears the pending state with the server's error on a refusal (or after 10 s).
- **Notices.** Unchanged server logic: exactly once per arrival, from trusted server-side handle, live only, never stored, no points, 30 s grace respected. Departing connection is removed from delivery at once on explicit leave.

### 2. DM presence (`presence_online.go`, `dm.go`)
Green dot and Online, grey dot and Offline, under the handle in the DM header. In memory only (no database writes, not part of any message). Sent only to someone with that conversation open, and not for blocked pairs (either direction). Several sessions per user count as one person. Offline is announced 10 s after the last connection ends, so a reconnect or brief backgrounding does not flap. Dead connections are removed by the existing server ping. Respects the existing "Show when I am online" setting (unknown settings count as hidden). Moderators get no special view of presence. The page clears the dot when its connection drops.

### 3. Profile photos (`photo.go`, `photo_storage.go`, `PhotoEditor.svelte`)
- Pick from gallery or files, crop and zoom preview, replace, remove. Illustrated avatars stay as the fallback (no photo, or image fails to load).
- Upload is HTTP `POST /api/photo` with the login token; `DELETE /api/photo` removes. The person comes only from the token.
- Server checks the real format (JPEG and PNG, by decoding), 3 MB upload limit, 48 to 4096 px sides, 12 million pixel cap, decodes and rebuilds a 512 px and a 96 px JPEG itself (metadata and hidden content are dropped). Keys are generated by the server and validated.
- Served at `/photo/<handle>`, thumbnail by default, `s=m` for profile size, immutable caching with a version in the address, ETag, `nosniff`. Avatars use lazy loading.
- Database holds only `photo_key` and `photo_ver` (migration `018_step18.sql`, also applied from `schema.sql`).
- Deleting an account removes the photo.
- **WebP:** the Go standard library has no WebP decoder and I did not add a dependency. The browser converts WebP to JPEG before upload. The server refuses a raw WebP upload with a clear error.
- **Storage:** interface with Supabase Storage, local folder (development only), and in-memory (tests). Photos are **off** unless `PHOTO_STORAGE` is configured. See README, "Profile photos".

### 4. DM inbox
Audited. Already correct: ordering by latest message, unread counts, previews decrypted in the browser, per-user association. Fixed: an incoming message while the inbox was open triggered a full inbox query, now the list updates locally; "No messages yet" showed while still loading, now "Loading your messages..."; unread rows are emphasised and labelled.

### 5. Notification preferences
Audited. Existing server-side controls (direct messages, tags and replies, tips, friend requests, friends-only DMs, show online) kept. Changed: the new-message pop up now follows the Direct messages setting; new device-only switch for room join and leave lines; clearer wording; Settings says there are no phone push messages. No push infrastructure added. Safety and moderation notices are unchanged.

### 6. Room audit
Verified by a new test: private and password rooms are not in the directory or search for outsiders, refused joins leave no membership, official-room Joined state clears on leaving. Member counts remain the number of people online in the room (unchanged); they are not a headcount of stored members. No other gaps found, nothing redesigned.

## Load test (same machine only)
Generator, server and database ran on one 1 CPU machine, so this is **not** production capacity. Real joins, leaves, room messages, DMs, lookups and forced reconnects were exercised. 30 s per stage: 100 clients passed, 300 clients passed (connection success 100%, no busy errors, message latency p50 1 ms, p95 5 ms, p99 14 ms at 300, Postgres connections max 3, reconnect success 100%). Report in `loadtest/results/step18-run-5de0.md`. Not tested: anything above 300, runs longer than about a minute (so no leak conclusion), a separate generator host. Pool limits were not changed.

## Known limits
- Three stale e2e scripts need updating for E2EE.
- WebP needs the browser to convert it.
- Photo changes by others appear on the next list or conversation refresh; a removed photo can show in cached old messages until the image fails to load and falls back.
- Presence for people who hide it looks offline to everyone, including moderators.
